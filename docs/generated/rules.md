## ACL-001

**ACL contains a 'permit any any' entry** · high · Access lists · applies to router, switch

**Risk.** An unrestricted permit turns an ACL into a blocklist: everything not explicitly denied above it is allowed, including new services, spoofed sources and lateral movement. As the first matching entry it disables the ACL.

**Remediation.** Replace it with the specific flows that are needed and finish with an explicit 'deny ip any any log'.

**References.** Cisco, Harden IOS Devices; NSA, Network Infrastructure Security Guide

## ACL-002

**Interface ACL does not end with a logged 'deny ip any any'** · low · Access lists · applies to router, switch

**Risk.** Packets dropped by the implicit deny at the end of an ACL are never logged, so scans and policy violations stay invisible to monitoring.

**Remediation.** End every interface ACL with 'deny ip any any log' (mind log rate limits on busy interfaces).

**References.** Cisco, Harden IOS Devices; NSA, Network Infrastructure Security Guide

## ACL-003

**ACL permits Telnet** · high · Access lists · applies to router, switch

**Risk.** Permitting TCP/23 allows clear-text remote administration across the network, exposing credentials to sniffing.

**Remediation.** Remove the entry; permit SSH (TCP/22) from the admin host only.

**References.** MITRE ATT&CK T1040 Network Sniffing; CIS Cisco IOS Benchmark

## ACL-004

**ACL is applied but not defined** · high · Access lists · applies to router, switch

**Risk.** IOS does not filter when the ACL named on an interface or line does not exist, so the interface or VTY line is silently wide open. A typo in the ACL name is enough.

**Remediation.** Define the ACL (or correct the name) and verify with 'show ip interface' and 'show access-lists'.

**References.** Cisco, Harden IOS Devices

## ACL-005

**ACL is defined but never applied** · low · Access lists · applies to router, switch

**Risk.** A dead ACL gives operators the false impression that traffic is filtered; it also hides stale policy.

**Remediation.** Apply the ACL where it is meant to act, or delete it.

**References.** Cisco, Harden IOS Devices

## ACL-006

**ACL entry is shadowed by an earlier entry** · low · Access lists · applies to router, switch

**Risk.** An entry that can never match is dead policy: the rule the author intended is not enforced and the ACL behaves differently from how it reads.

**Remediation.** Reorder so the specific entry comes first, or remove the redundant one.

**References.** Cisco, Harden IOS Devices

## ACL-007

**Router applies no ACL on any routed interface** · medium · Access lists · applies to router

**Risk.** With no traffic filtering every attached segment can reach every other: there are no security zones, and one compromised host can scan and attack the whole network.

**Remediation.** Define zone policy ACLs and apply them with 'ip access-group <name> in' on the interface closest to the source.

**References.** NSA, Network Infrastructure Security Guide; Cisco, Harden IOS Devices

## ACL-008

**ACL entry uses syntax the auditor does not understand** · info · Access lists · applies to router, switch

**Risk.** Entries that cannot be parsed are ignored by the auditor and the policy simulator, so their effect is not assessed.

**Remediation.** Review the entry manually, or extend the ACL parser if the syntax is valid IOS.

## AUTH-001

**VTY lines accept remote logins without authentication** · critical · Access control · applies to router, switch

**Risk.** 'no login' on a VTY line gives an exec shell to anyone who can reach the device over the network. Together with a missing or weak enable secret this is complete device takeover with no credentials at all.

**Remediation.** Require authentication on every VTY line: create per-user accounts ('username <name> privilege 15 secret <strong-secret>') and use 'login local' under 'line vty 0 15', or point 'login authentication' at an AAA method list.

**References.** MITRE ATT&CK T1078 Valid Accounts; Cisco, Harden IOS Devices; CIS Cisco IOS Benchmark

## AUTH-002

**Console or AUX line has no authentication** · medium · Access control · applies to router, switch

**Risk.** A line without 'login' gives an unauthenticated exec session to anyone with physical access, a serial console server or a modem on the AUX port. Out-of-band paths bypass every network-based control.

**Remediation.** Console: 'line con 0' / 'login local' / 'exec-timeout 5 0' / 'logging synchronous'. AUX: disable it ('line aux 0' / 'no exec' / 'transport input none') unless a modem is genuinely required.

**References.** Cisco, Harden IOS Devices; CIS Cisco IOS Benchmark

## AUTH-003

**VTY lines use one shared line password instead of per-user accounts** · medium · Access control · applies to router, switch

**Risk.** A single password shared by every administrator leaves no per-person audit trail, cannot be revoked for one person without changing it for all, and is easy to guess, share or leak.

**Remediation.** Use 'login local' with one 'username ... secret ...' per administrator (or AAA with TACACS+/RADIUS).

**References.** Cisco, Harden IOS Devices; NSA, Network Infrastructure Security Guide

## AUTH-004

**Line requires a password but none is configured** · low · Access control · applies to router, switch

**Risk.** 'login' without a line password makes IOS reject every attempt ('Password required, but none set'). The line is unusable, and the usual quick fix - adding one shared password - is weaker than per-user authentication.

**Remediation.** Switch the line to 'login local' and create per-user accounts with 'username ... secret ...'.

**References.** Cisco, Harden IOS Devices

## CRED-001

**No enable secret is configured** · high · Credentials · applies to router, switch

**Risk.** With no enable secret, privileged EXEC is not password-protected at the console, so physical or console-server access means full control; remote users cannot elevate, which tempts administrators into giving every account privilege 15 instead.

**Remediation.** Set a strong, unique secret: 'enable secret <value>' (stored as a hash). Do not use 'enable password'.

**References.** CIS Cisco IOS Benchmark; Cisco, Harden IOS Devices; NSA, Cisco Password Types: Best Practices

## CRED-002

**Credentials are stored in clear text or in reversible form** · high · Credentials · applies to router, switch

**Risk.** Type 0 is plain text and type 7 is a reversible Vigenere-style encoding that public tools undo instantly. Anyone who can read a configuration backup, a TFTP capture or a screen share recovers the password.

**Remediation.** Replace 'enable password' with 'enable secret'; use 'username <name> secret <value>' instead of 'password'; prefer 'login local' to line passwords. Enable 'service password-encryption' only as a second line of defence.

**References.** MITRE ATT&CK T1552.001 Unsecured Credentials: Credentials In Files; NSA, Cisco Password Types: Best Practices; CIS Cisco IOS Benchmark

## CRED-003

**Weak password hash algorithm (type 4)** · medium · Credentials · applies to router, switch

**Risk.** Type 4 secrets use a SHA-256 construction without a proper salt or iteration count, so they can be cracked offline much faster than type 5 and far faster than type 8 or 9. Cisco and the NSA advise against using it.

**Remediation.** Re-enter the secret with a stronger type where the platform supports it ('algorithm-type scrypt' for type 9).

**References.** NSA, Cisco Password Types: Best Practices

## CRED-004

**A well-known or default password is in use** · critical · Credentials · applies to router, switch

**Risk.** Passwords such as 'cisco' or 'admin' are the first guesses of every attacker and scanner. The check works even on hashed values because the salt is stored with the hash.

**Remediation.** Replace the credential with a unique passphrase (14+ characters) and rotate anything derived from it.

**References.** MITRE ATT&CK T1078.001 Valid Accounts: Default Accounts; MITRE ATT&CK T1110.001 Brute Force: Password Guessing; NSA, Cisco Password Types: Best Practices

## CRED-005

**'service password-encryption' is not enabled** · medium · Credentials · applies to router, switch

**Risk.** Line and username passwords that are not otherwise hashed appear in clear text in 'show running-config'. The service adds type 7 obfuscation, which is weak, but it stops casual disclosure by shoulder-surfing or a pasted screenshot.

**Remediation.** 'service password-encryption', and store credentials with 'secret' so they are hashed in the first place.

**References.** CIS Cisco IOS Benchmark; Cisco, Harden IOS Devices

## INT-001

**Proxy ARP is enabled on routed interfaces** · low · Interfaces · applies to router

**Risk.** With proxy ARP the router answers ARP requests on behalf of other subnets. This masks misconfigured masks, lets hosts without a gateway reach other segments through the router, and widens the effect of ARP spoofing.

**Remediation.** 'no ip proxy-arp' on every routed interface or subinterface.

**References.** CIS Cisco IOS Benchmark; Cisco, Harden IOS Devices

## INT-002

**Directed broadcasts are forwarded** · medium · Interfaces · applies to router, switch

**Risk.** A packet sent to a subnet's directed-broadcast address is turned into a link-layer broadcast, so one spoofed ICMP echo makes every host answer the victim (a smurf amplification attack).

**Remediation.** 'no ip directed-broadcast' on every interface.

**References.** MITRE ATT&CK T1498 Network Denial of Service; CIS Cisco IOS Benchmark

## L2-001

**Switch ports negotiate trunking (DTP dynamic mode)** · medium · Layer 2 · applies to switch

**Risk.** A port left in dynamic auto/desirable mode will turn itself into an 802.1Q trunk if the device on the other end asks it to. An attacker's host (or a rogue switch) then receives every VLAN the trunk carries.

**Remediation.** Set 'switchport mode access' on every end-user port and 'switchport mode trunk' + 'switchport nonegotiate' on uplinks.

**References.** Cisco, Harden IOS Devices; CIS Cisco IOS Benchmark; NSA, Network Infrastructure Security Guide

## L2-002

**Trunk ports still send DTP frames** · low · Layer 2 · applies to switch

**Risk.** A static trunk without 'switchport nonegotiate' keeps advertising DTP, which leaks the link's role and invites negotiation attempts.

**Remediation.** Add 'switchport nonegotiate' to every static trunk.

**References.** Cisco, Harden IOS Devices; CIS Cisco IOS Benchmark

## L2-003

**Trunk native VLAN is the default VLAN 1** · medium · Layer 2 · applies to switch

**Risk.** Native-VLAN frames cross a trunk untagged. A host in the native VLAN can double-tag frames so that the first switch strips the outer tag and the second delivers the packet into another VLAN (VLAN hopping).

**Remediation.** Use an unused VLAN as native VLAN on every trunk: 'switchport trunk native vlan 999' (no ports or SVI in it).

**References.** Cisco, Harden IOS Devices; CIS Cisco IOS Benchmark; NSA, Network Infrastructure Security Guide

## L2-004

**Trunk carries every VLAN** · low · Layer 2 · applies to switch

**Risk.** A trunk that allows all VLANs widens broadcast domains and extends the reach of VLAN-hopping and spanning-tree attacks to VLANs that do not belong on that link.

**Remediation.** Prune each trunk: 'switchport trunk allowed vlan 10,20,99'.

**References.** Cisco, Harden IOS Devices; CIS Cisco IOS Benchmark

## L2-005

**Port security is not enabled on edge ports** · medium · Layer 2 · applies to switch

**Risk.** Without port security anyone can plug an unknown device into a live port, or flood the switch with spoofed source MACs until its CAM table overflows and it forwards traffic like a hub, exposing other users' frames.

**Remediation.** On access ports: 'switchport mode access', 'switchport port-security', 'switchport port-security maximum 2', 'switchport port-security mac-address sticky', 'switchport port-security violation restrict' (or shutdown).

**References.** MITRE ATT&CK T1200 Hardware Additions; MITRE ATT&CK T1557 Adversary-in-the-Middle; Cisco, Harden IOS Devices; CIS Cisco IOS Benchmark

## L2-006

**PortFast with BPDU Guard is missing on edge ports** · medium · Layer 2 · applies to switch

**Risk.** A switch (or a host running a bridging tool) plugged into an edge port can send BPDUs, win the root-bridge election and pull traffic through itself, or trigger repeated reconvergence and an outage.

**Remediation.** 'spanning-tree portfast' + 'spanning-tree bpduguard enable' per port, or 'spanning-tree portfast default' + 'spanning-tree portfast bpduguard default' globally.

**References.** Cisco, Harden IOS Devices; CIS Cisco IOS Benchmark; NSA, Network Infrastructure Security Guide

## L2-007

**Unused ports are enabled** · medium · Layer 2 · applies to switch

**Risk.** A live, unconfigured port is an open door for anyone with physical access: plug in and you are on the network (usually in VLAN 1).

**Remediation.** 'shutdown' every unused port and park it in an unused VLAN ('switchport access vlan 999').

**References.** MITRE ATT&CK T1200 Hardware Additions; CIS Cisco IOS Benchmark; NSA, Network Infrastructure Security Guide

## L2-008

**Active ports use the default VLAN 1** · medium · Layer 2 · applies to switch

**Risk.** VLAN 1 cannot be deleted and carries control-plane protocols (CDP, VTP, DTP, STP). Placing users there removes any segmentation and exposes those protocols to them.

**Remediation.** Assign end-user ports to purpose-built VLANs ('switchport access vlan 10') and keep VLAN 1 empty.

**References.** Cisco, Harden IOS Devices; CIS Cisco IOS Benchmark; NSA, Network Infrastructure Security Guide

## L2-009

**Management address sits in VLAN 1** · low · Layer 2 · applies to switch

**Risk.** Managing the switch from VLAN 1 mixes management with the default VLAN that every unconfigured port belongs to.

**Remediation.** Move the management SVI to a dedicated management VLAN ('interface Vlan99') and shut down 'interface Vlan1'.

**References.** Cisco, Harden IOS Devices; NSA, Network Infrastructure Security Guide

## L2-010

**VTP is not in transparent or off mode** · low · Layer 2 · applies to switch

**Risk.** In VTP server or client mode, a switch advertising a higher revision number overwrites the VLAN database of every switch in the domain - by accident or on purpose - deleting VLANs and causing an outage.

**Remediation.** 'vtp mode transparent' (or 'vtp mode off' where supported) and manage VLANs per switch.

**References.** Cisco, Harden IOS Devices; CIS Cisco IOS Benchmark

## L2-011

**DHCP snooping is not enabled** · medium · Layer 2 · applies to switch

**Risk.** Any port can answer DHCP requests. A rogue DHCP server hands clients its own default gateway or DNS server (a man-in-the-middle position) or exhausts the address pool (denial of service), and the switch has no binding table that ties each IP address to a port - which Dynamic ARP Inspection also needs.

**Remediation.** 'ip dhcp snooping' and 'ip dhcp snooping vlan <ids>'; mark only the uplink toward the real DHCP server with 'ip dhcp snooping trust'; rate-limit client ports with 'ip dhcp snooping limit rate 15'.

**References.** MITRE ATT&CK T1557 Adversary-in-the-Middle; Cisco, Harden IOS Devices; NSA, Network Infrastructure Security Guide

## L2-012

**Dynamic ARP Inspection is not enabled** · medium · Layer 2 · applies to switch

**Risk.** Without Dynamic ARP Inspection any host can poison its neighbours' ARP caches (ARP spoofing) and sit between them and their gateway, reading or altering traffic that never leaves the VLAN, which no router ACL can see.

**Remediation.** 'ip arp inspection vlan <ids>' on VLANs whose hosts get their addresses through DHCP snooping; trust only uplinks ('ip arp inspection trust'); use ARP ACLs for statically addressed hosts.

**References.** MITRE ATT&CK T1557.002 Adversary-in-the-Middle: ARP Cache Poisoning; Cisco, Harden IOS Devices; NSA, Network Infrastructure Security Guide

## LOG-001

**No remote syslog server** · medium · Logging · applies to router, switch

**Risk.** Without an off-box log destination the only evidence lives in volatile device memory: a reload, a full buffer or an attacker erases it, and nothing can be correlated or alerted on centrally.

**Remediation.** 'logging host <syslog-server>' with 'logging trap informational' and a stable 'logging source-interface'.

**References.** CIS Cisco IOS Benchmark; Cisco, Harden IOS Devices; NSA, Network Infrastructure Security Guide

## LOG-002

**Log messages carry no date and time** · low · Logging · applies to router, switch

**Risk.** Messages stamped only with uptime cannot be ordered against other systems' logs, so events cannot be correlated during an investigation.

**Remediation.** 'service timestamps log datetime msec' and 'service timestamps debug datetime msec'.

**References.** CIS Cisco IOS Benchmark

## LOG-003

**No time source (NTP) is configured** · low · Logging · applies to router, switch

**Risk.** Timestamps are only useful if every device agrees on the time; without NTP, clocks drift and logs cannot be correlated.

**Remediation.** 'ntp server <address>' (ideally authenticated with 'ntp authenticate' and 'ntp trusted-key').

**References.** CIS Cisco IOS Benchmark; NSA, Network Infrastructure Security Guide

## MGMT-001

**Telnet is accepted for remote management** · high · Management plane · applies to router, switch

**Risk.** Telnet sends credentials and every command in clear text. Anyone on the path - or an attacker who can sniff or ARP-spoof the segment - captures the administrator's password and can replay the session.

**Remediation.** Allow only SSH on the VTY lines: 'line vty 0 15' / 'transport input ssh'.

**References.** MITRE ATT&CK T1040 Network Sniffing; Cisco, Harden IOS Devices; CIS Cisco IOS Benchmark; NSA, Network Infrastructure Security Guide

## MGMT-002

**VTY access is not restricted to management hosts** · medium · Management plane · applies to router, switch

**Risk.** Without an 'access-class', every host that can route to any interface of the device may attempt to log in or exploit the management services. A management ACL shrinks that audience to a few administrator addresses.

**Remediation.** Define 'ip access-list standard VTY-MGMT' permitting only the admin host(s) and a final 'deny any log', then apply 'access-class VTY-MGMT in' on every VTY line.

**References.** Cisco, Harden IOS Devices; CIS Cisco IOS Benchmark; NSA, Network Infrastructure Security Guide

## MGMT-003

**Idle management sessions never time out** · medium · Management plane · applies to router, switch

**Risk.** An exec session without an idle limit stays open indefinitely. A forgotten console or SSH session on an unattended terminal can be used by anyone who walks up to it.

**Remediation.** Set 'exec-timeout 5 0' (five minutes or less) under 'line con 0', 'line vty 0 15' and 'line aux 0'.

**References.** CIS Cisco IOS Benchmark; Cisco, Harden IOS Devices

## MGMT-004

**No login banner** · low · Management plane · applies to router, switch

**Risk.** Without a warning banner there is no notice that access is restricted and monitored, which weakens the basis for enforcing the acceptable-use policy. (Wording should come from your organisation's legal team.)

**Remediation.** Configure 'banner login' (or 'banner motd') with an authorised-use notice that reveals no device details.

**References.** CIS Cisco IOS Benchmark; Cisco, Harden IOS Devices

## MGMT-005

**HTTP management server is enabled** · high · Management plane · applies to router, switch

**Risk.** The built-in web server exposes an administration interface over unencrypted HTTP, so credentials and sessions can be sniffed, and the web UI has been affected by several remotely exploitable vulnerabilities.

**Remediation.** 'no ip http server' (and 'no ip http secure-server' unless the HTTPS UI is actually needed and restricted).

**References.** MITRE ATT&CK T1040 Network Sniffing; CIS Cisco IOS Benchmark; Cisco, Harden IOS Devices

## MGMT-006

**AUX port is enabled** · medium · Management plane · applies to router

**Risk.** The AUX port is an out-of-band exec path that is easy to forget. If a modem or terminal server is attached it bypasses every network control, and an unauthenticated AUX line is an open door.

**Remediation.** 'line aux 0' / 'no exec' / 'transport input none' / 'transport output none'.

**References.** CIS Cisco IOS Benchmark; Cisco, Harden IOS Devices

## MGMT-007

**SNMP community string is a well-known default** · critical · Management plane · applies to router, switch

**Risk.** 'public' and 'private' are the first strings any scanner tries. Read access discloses configuration, routing and ARP tables; read-write access lets an attacker change the device over SNMP.

**Remediation.** Remove the community; use SNMPv3 with authentication and encryption ('snmp-server group ... v3 priv').

**References.** MITRE ATT&CK T1602.001 Data from Configuration Repository: SNMP (MIB Dump); Cisco, Harden IOS Devices; CIS Cisco IOS Benchmark

## MGMT-008

**SNMP read-write community is configured** · high · Management plane · applies to router, switch

**Risk.** SNMPv1/v2c authenticates with a clear-text community string. A read-write community lets anyone who learns the string change configuration remotely.

**Remediation.** Remove 'RW' communities; if write access is unavoidable use SNMPv3 priv with a restricted view and ACL.

**References.** MITRE ATT&CK T1602.001 Data from Configuration Repository: SNMP (MIB Dump); CIS Cisco IOS Benchmark

## MGMT-009

**AAA is not enabled (local-only authentication)** · low · Management plane · applies to router, switch

**Risk.** Without AAA there is no central account lifecycle, command authorisation or accounting: every device keeps its own accounts and nothing records who ran which command.

**Remediation.** Enable 'aaa new-model', authenticate against TACACS+/RADIUS with a local fallback ('aaa authentication login default group tacacs+ local'), and add command accounting.

**References.** CIS Cisco IOS Benchmark; NSA, Network Infrastructure Security Guide

## MGMT-010

**SSH version 2 is not enforced** · medium · Management plane · applies to router, switch

**Risk.** Unless 'ip ssh version 2' is set, IOS also accepts the legacy SSH-1 protocol, which has known cryptographic weaknesses. If SSH is not configured at all, administrators fall back to Telnet.

**Remediation.** Set a domain name, generate an RSA key of at least 2048 bits ('crypto key generate rsa modulus 2048') and enforce 'ip ssh version 2'; add 'ip ssh time-out 60' and 'ip ssh authentication-retries 3'.

**References.** MITRE ATT&CK T1021.004 Remote Services: SSH; CIS Cisco IOS Benchmark; Cisco, Harden IOS Devices

## RTE-001

**Routing updates are not authenticated** · high · Routing · applies to router, switch

**Risk.** Any host that can send packets to an interface running the protocol can inject routes - a default route or more-specific prefixes - and silently redirect, intercept or black-hole traffic.

**Remediation.** RIPv2: 'key chain' + 'ip rip authentication mode md5' + 'ip rip authentication key-chain'. OSPF: 'area <n> authentication message-digest' (or per-interface) with 'ip ospf message-digest-key'. Also make user-facing interfaces passive.

**References.** MITRE ATT&CK T1557 Adversary-in-the-Middle; Cisco, Harden IOS Devices; CIS Cisco IOS Benchmark; NSA, Network Infrastructure Security Guide

## RTE-002

**RIP version 1 is in use** · medium · Routing · applies to router, switch

**Risk.** RIPv1 is classful (updates carry no subnet masks, so VLSM designs cannot be expressed), broadcasts its updates and has no authentication, so any host on the segment can spoof a neighbour.

**Remediation.** 'router rip' / 'version 2' / 'no auto-summary' with authentication, or migrate to OSPF.

**References.** Cisco, Harden IOS Devices; NSA, Network Infrastructure Security Guide

## RTE-003

**Routing protocol is active on every interface (no passive-interface)** · medium · Routing · applies to router, switch

**Risk.** Without passive interfaces the router sends and accepts routing updates on user-facing segments too, so a host there can learn the topology, form adjacencies or inject routes.

**Remediation.** Use 'passive-interface default' under the routing process, then 'no passive-interface <link>' only on interfaces that face routers.

**References.** Cisco, Harden IOS Devices; NSA, Network Infrastructure Security Guide; CIS Cisco IOS Benchmark

## RTE-004

**OSPF or RIP uses plain-text authentication** · medium · Routing · applies to router, switch

**Risk.** Plain-text authentication puts the key in every routing packet. Anyone who can sniff the segment learns it and can then forge updates as a trusted neighbour.

**Remediation.** Use MD5 (or HMAC-SHA with key chains where supported): 'ip ospf authentication message-digest'.

**References.** Cisco, Harden IOS Devices; NSA, Network Infrastructure Security Guide

## SVC-001

**CDP is running** · low · Services · applies to router, switch

**Risk.** CDP advertises the model, IOS version, interface names and management addresses to anything on the link, in clear text and without authentication. Attackers use it for reconnaissance, and CDP parsers have been affected by remotely exploitable bugs. The exposure matters most on ports that face users.

**Remediation.** 'no cdp run' globally, or 'no cdp enable' on every interface that does not face a trusted neighbour.

**References.** MITRE ATT&CK T1016 System Network Configuration Discovery; CIS Cisco IOS Benchmark; NSA, Network Infrastructure Security Guide

## SVC-002

**IP source routing is enabled** · low · Services · applies to router

**Risk.** Source-routed packets let the sender dictate the path they take, which can bypass routing-based controls and help spoofing or firewall evasion.

**Remediation.** 'no ip source-route'.

**References.** CIS Cisco IOS Benchmark; Cisco, Harden IOS Devices

## SVC-003

**Legacy or unneeded services are enabled** · medium · Services · applies to router, switch

**Risk.** Small servers, finger, BOOTP, PAD, remote copy/shell and similar services add network-reachable attack surface that a modern network never needs; several are classic reconnaissance or denial-of-service targets.

**Remediation.** Disable each one explicitly, e.g. 'no service tcp-small-servers', 'no service udp-small-servers', 'no ip bootp server'.

**References.** CIS Cisco IOS Benchmark; Cisco, Harden IOS Devices

## SVC-004

**Device still uses the default hostname** · low · Services · applies to router, switch

**Risk.** Devices called 'Router' or 'Switch' cannot be told apart in syslog, SNMP traps, SSH host-key warnings or change records, which makes incident response and change control error-prone.

**Remediation.** Give every device a unique, role-based name: 'hostname HQ-EDGE'.

**References.** CIS Cisco IOS Benchmark
